These changes remove interpreter trips for useful scalar/vector work. They do not yet remove the largest main-thread, spin-worker and queue costs. Five isolated gains do not establish a 5× game gain.

Five guarded native completions

CWDE sign extension, 32-bit memory division, legacy MOVAPS loads and stores, and VPMADDWD now stay in translated code. Memory uses existing TLB, helper, page and ordering proofs. The division guard sends zero/high-half cases to the unchanged interpreter. Legacy MOVAPS preserves upper vector state; VPMADDWD matches the interpreter's upper clearing and wraps the signed pair sum. The valid −32768 overflow case also exposed a Debug trap in the old interpreter; that sum now wraps explicitly.

Both variants keep the block JIT enabled. The baseline forces only these new forms through the production interpreter. Each sample performs 100,000 operations with equal retired instructions, full register/vector/flag and memory comparisons, and 100,000 → 0 targeted fallbacks. Compilation, warm-up and setup are excluded. Small fixtures do not reproduce Halo's full working set.

Actual worker host CPU


This new run includes real host-thread CPU. CPU includes the worker's compute and kernel CPU and excludes off-core/parked time; it does not distinguish useful computation from spinning. Workers overlap, so their CPU totals are not a frame budget. The UI owner, native library workers and GPU execution remain unmeasured.




What still dominates


  • The main guest worker consumed about 786 seconds of CPU over 840 seconds elapsed. Its large translated working set and critical-section regions remain candidates.
  • Two XThread workers consumed about 570 and 573 seconds of CPU. Both repeatedly sample the spin-lock acquisition region at 0x14035ce00. Instruction samples alone cannot assign milliseconds to that region.
  • GPU Commands consumed about 366 seconds of host CPU. Queue-submit elapsed was 287.455 seconds, including 267.081 seconds of room wait. Neither number measures actual GPU execution.
  • UI handoff maxima reach 747 ms queued and 771 ms running; their scene and critical-path relationship are not logged. Async evidence I/O reaches 609.719 ms on its separate worker.
  • The first four new paths account for roughly 5.87 seconds of count-weighted fallback elapsed estimates in this run. Qualifying guard coverage and the missing multiply-add rank are unknown. That is much smaller than the dominant costs; the offline ratios alone do not justify a large FPS forecast.
