The model

Translated instructions are a property of Xenia's work, not of Rosette's speed, and GPU Commands' per-frame count is almost exactly linear in draw work. Its busy time follows from its translated-instruction rate relative to its saturated rate in the same window.

Offline proof: Xenia's GPU register writes

Every PM4 register write Xenia performs is a loop iteration around a virtual VulkanCommandProcessor::WriteRegister, which calls the base CommandProcessor::WriteRegister and updates a dirty bit: type-0 packets (ExecutePacketType0), SET_CONSTANT ranges (WriteRegisterRangeFromRing) and LOAD_ALU_CONSTANT (WriteRegistersFromMem). Translated, one register is 48–61 instructions in five to eight blocks, and the block hops dominate.

Change: a translated block starting at one of those three loop heads calls a native gate before loading its register cache. At a loop head every caller-saved register and flag is dead, so the gate runs the iterations natively through this executor's own TLB (the translator's admission rules, acquire/release lanes), then leaves exactly the registers, stack slots and loop exit the final iteration would. It stops at an iteration boundary, before any side effect, on a special or logged register, an unadmitted page, a different virtual WriteRegister or a changed image; Xenia's own code then runs that iteration. All five functions must match the shipped bytes before any gate is compiled.

How close to a locked 30 FPS?


A frame takes the longer of GPU Commands' busy time and the floor set elsewhere (MAIN is 94% busy in every window; the light windows sit at that floor). The calculator applies the measured per-write saving to GPU Commands' busy-time fit. Registers written per draw are not yet measured live; the default (≈230, 90% through small type-0 packets) is derived from this run: Xenia executed 91.04M packets for 3.44M native draws, the sampled indirect buffer is 77% type-0 packets carrying ~9.6 registers each (about 23.6 packets and 230 registers per descriptor update). That type-0 figure is an upper estimate (inline shader loads in the same sample would lower it); constants loaded from memory add to the total. The next run's PE64 XENIA REGISTER WRITES counters replace this estimate.
