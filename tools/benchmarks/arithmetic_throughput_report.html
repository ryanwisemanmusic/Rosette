Complete translated paths

Arithmetic: width-matched ARM ADD/SUB supplies overflow, carry, sign and zero flags. Ordinary arithmetic reuses its fresh NZCV; other admitted paths derive it from intact operands. Parity, auxiliary carry, untouched flags and narrow/carry-in behavior remain exact. The decoder oracle checks 6,144 edge/random/alias cases. Existing fused readers, atomic updates and carry tests also run.

Misaligned scalar memory: an admitted eight-byte span uses two ordered word accesses when four-byte aligned, four halfword accesses when two-byte aligned, and the original byte sequence at odd addresses. The complete span is checked before access; acquire/release ordering and helper/fault boundaries remain. 480 baseline/candidate route cases cover widths, alignment, read/write refusal, abort and page crossing; a two-thread fixture checks 50,000 payload publications.

What explains the apparent 20 FPS ceiling?


There is no 20 FPS setting in the measured present path. Its ceiling is 30 FPS, and the swapchain reports immediate mode. During the last 7,562 present intervals, the ceiling added just 23 ms in total (about 0.003 ms per interval). Ingress averaged 73.95 ms in that broad interval, including scene changes and guest execution. This rules out Rosette’s present ceiling as the explanation for sustained slow gameplay; it does not establish that one CPU or GPU component imposes a fixed 50 ms limit.


The final 40 WSI windows range from 7.068 to 19.873 FPS. User observations are 11–18 typical, 7–9 during slower movement and about 20 peak. The windows have no scene/camera labels. WSI cadence measures accepted native presents, not simulation speed.



20 FPS is 50 ms/frame. 22 FPS needs 45.45 ms, and 25 needs 40 ms: 9.1% and 20% less critical-frame time. Only measured work on that critical path can deliver these savings; parked time, CPU totals on other workers and overlapping scope totals cannot be added as removable frame time.

What still dominates


  • MAIN uses 809.929 s CPU / 850.009 s elapsed; GPU Commands 625.439 s CPU, RENDER 480.939 s. These are candidates for native execution and bridge work, not a partition of frame time.
  • 64.455 million transfer fallbacks target hooked functions; 8.196 million target imports. CALL/JMP estimates overlap import work and include scheduling/locks. The largest totals are not exclusive CPU.
  • Descriptor binding/updating consume 37.112 / 34.445 s of bridge elapsed time. Queue submit 26.214 s, pipeline create 12.917 s. Actual native compiler/GPU execution and dependency fractions remain unmeasured.
  • Two XThreads use 520.134 / 510.700 s CPU and still sample the spin-lock region. Instruction samples cannot attribute their CPU time to that region.
