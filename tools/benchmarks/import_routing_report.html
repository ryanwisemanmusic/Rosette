Two enabled changes · full call paths measured

Wait-object positions. The latest run reaches 474 live wait objects. A private host-thread cache remembers an index, validates the current owner, table range and handle on every hit, then reads the current object. Closure, reuse and readiness remain live; wait, event, mutex, timeout and runtime-lock semantics stay intact. No per-call allocation; 256 bounded slots, about 6 KiB per participating host thread.

Immutable Vulkan ABI facts. A copied-name cache retains ownership, argument widths and float count for non-command entry points. Every call still performs the live loader/native-capability checks. Changed bytes at a reused name address invalidate the hit. Command APIs bypass this cache because their measured benefit was flat. No native device or resource pointer is cached.

100,000 operations per sample, seven alternating ReleaseFast pairs after compilation. Ordinary NT fixtures execute real guest CALL instructions, JIT, import dispatch, ABI and runtime-lock work with the same 400,001 retired instructions and checked state. Vulkan fixtures use the complete Windows/SysV adapter with counted CPU callbacks; no GPU commands execute. Controls disable only the named cache in the final implementation, not an old installed build. Raw lookup ratios overlap complete-call ratios and must not be multiplied.
