Two enabled changes · complete ordinary dispatch measured

Dynamic stub positions. Repeated calls used a linear search of the registered dynamic stubs. A private host-thread cache now remembers the position, rechecking the live registry range and address on every hit. It copies the current record and holds no borrowed names or native object pointers. Direct PE import indexing is unchanged.

CALL metadata. Recovering an import callsite repeatedly fetched and decoded up to 15 instruction positions. The private cache now retains decoded candidates, rechecks all 15 source bytes, and resolves register and memory operands live. Candidate preference remains the original shortest matching CALL. Code changes, mapping boundaries, bound worker operands and diagnostic exclusions are covered.

Each sample executes 100,000 ordinary Vulkan import handlers through real guest CALL instructions, the production process dispatcher and its existing ABI/runtime-lock work. The backend is a CPU-only checksum callback; no Vulkan driver or GPU executes. Controls disable only these two caches, with the block JIT on in both variants. Registry construction, warm-up and compilation are excluded; compiled counts stay unchanged during timing. Counter accumulation is outside the registry scan loop. Controls use the final implementation, not an earlier installed executable.

New telemetry · available after rebuild and an ordinary run
