Complete generated-code chains

Native chain branch layout: a match in the first direct-successor slot now falls through into the unchanged live-slot, address and generation proof. The search through later slots and the jump cache sits off that common path. Indirect transfers retain their existing search order. The adaptive register allocator and publication rules are unchanged.

Direct scalar operations: eligible 32/64-bit shifts, rotations, NOT and NEG operate in their existing private register cache. Shifts, rotations and NEG require dead flag outputs. Narrow operands, live flags and zero rotations retain the ordinary implementation. This removes temporary moves without changing TSO or guest memory accesses.

Each row compares the same final implementation with an internal feature control. Seven alternating ReleaseFast pairs, after compilation. Full state and retirement are checked; setup is excluded. The combined row measures both changes together in one workload; other ratios must not be multiplied. The 24 FPS target


The supplied stationary Custom Game clip repeatedly shows about 19–20 FPS. Its final 32 logged presentation intervals average 49.853 ms (p95 53.050, max 53.483). The campaign log ends at 217.651 ms per presented frame; these are different scenes and loads.


20 → 24 FPS requires 50 → 41.667 ms: 8.333 ms less critical-frame time, or 16.7%. Total CPU on parallel workers, parked waits and overlapping bridge spans cannot be added into that budget.




Rejected register-residency prototypes
Two prototypes retained registers across blocks using one fixed map. Several pure chains slowed down, and the short-exit case regressed. Both were removed from the runtime. Their timings are retained here and excluded from the calculator.

Actual host worker CPU


THREAD_CPUTIME_ID includes compute and kernel CPU, excludes parked/off-core time. Worker lifetimes and work overlap. Busy polling is not classified as useful work. Per-worker maxima and useful-work fractions remain unknown.


Why investigate native chains?


  • Custom: MAIN executes 7.156 billion blocks and 208.991 billion retired instructions while consuming 352.619 s CPU. RENDER executes 8.353 billion blocks / 189.527 billion retired instructions and uses 217.744 s CPU.
  • Campaign: MAIN uses 788.503 s CPU, GPU Commands 609.232 s and RENDER 531.737 s. MAIN and RENDER execute 12.925 / 26.514 billion blocks. These totals overlap and do not establish their exclusive per-frame cost.
  • Custom descriptor bind/update elapsed totals are 12.608 / 10.278 s; campaign 39.785 / 37.635 s. Campaign fence elapsed is 65.750 s, averaging 26.565 ms over 2,475 calls. These spans include waits; GPU dependency time and driver CPU remain unresolved.
  • The features' live qualification and first-slot hit / scalar-operation shares are unknown in these pre-change logs. A native-path ratio can only help FPS in proportion to its measured frame-critical share.
